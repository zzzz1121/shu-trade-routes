# 《蜀地钱路》视觉规范 V0.1 · 参考图场景版

## 视觉依据

以用户最新提供的地图截图为构图依据，原图保存在 `docs/references/approved-game-ui.png`。调用内置 imagegen 编辑原图，去除文字、白色文字底板、圆形地点标记和白色路线虚线，保留建筑、石桥、河道、道路地面、树木、岩石、围墙和布匹陈设。生成结果为 `miniapp/assets/approved/town-atlas.png`。approved 目录表示参考方向已确认，不代表生成结果已获最终美术验收。

地图保留参考图的现代数字插画、斜俯视中式木构建筑、灰蓝屋顶、柔和投影和青绿水岸。图像不是逐像素复制，局部植被、瓦片、货物细节有生成式变化。使用原始截图比例 634:522，不拉伸成正方形，不加入额外氛围装饰。

## 实现边界与分层

本版采用场景图集分区方案：同一张无文字场景图，按 `miniapp/ui/scene.js` 的六个建筑区域与剩余地形区域分别裁切显示。地形层、建筑区域层、代码道路层、交互节点层及页面 UI 分开。各分区拼合完整构图，不在 PNG 上烘焙动态文字或按钮。

这不是六张已抠图的透明建筑精灵：当前矩形建筑区仍包含周边地面，暂不支持随意移动建筑而不修补地形。未来需要重新布置地图时，应先补充无建筑底图与独立透明建筑。替换素材和展示坐标不需要修改规则引擎；分区坐标不能作为路网或交易判定。

动态白色虚线根据原关卡六条边绘制：货仓—收费桥—布铺—交付商行；货仓—街巷—后巷—布铺—交付商行。原参考图未清晰画出的布铺至交付商行连接也由代码补齐。道路地面本身属于插画。

集中在 `miniapp/styles/tokens.css`，组件样式在 `miniapp/styles/game.css`；浏览器和小程序共用。地图构图比例及锚点集中在 `miniapp/ui/scene.js`。

## 固定屏和操作区

优先验收375×812、390×844、430×932。整页固定于视口，顶部任务与步数、中央等比例地图、底部钱袋与交易面板共同显示，不上下滑动。规则说明使用三页弹层。保留安全区域 padding；真实小程序安全区域仍待真机验证。

底部资源行展示铁钱、交子、布料及五格负重；初始8铁钱属于货仓，标注「待装载8/5」，不会允许超重出发。兑换前预览、兑换后确认出发、到店混合支付及交付都由现有状态驱动。不同操作复用底部空间，不添加静态装饰按钮。

## 仍需验收

地图图集生成细节、资源图标与场景笔触的一致性、原生图片重复引用的内存表现，以及小红书包体与真机渲染。当前通过的是浏览器测试，没有声称官方开发者工具验证通过。

## 界面文案精简

移除地图下方教学小字、撤销旁重复说明、首页底部重复文案、默认备钱提醒及规则中的历史币值免责声明。保留操作相关的手续费、支付/负重预览、错误原因与资源变化。无反馈内容时收起反馈行，不预留空行。历史背景说明仅留在项目文档中。

## 上下场景延展

新增 `miniapp/assets/approved/town-extended.png`，由内置 imagegen 对中央图集向上下扩图。独立 scene-continuation 底层填满任务区与钱袋区之间的弹性高度，保留原中央图集的634:522比例和六个节点锚点。中央图集的上下边缘以22px蒙版过渡到延展地形；文字、路线和点击层不参与蒙版。地形进入底部面板后方，避免留白带。全场景继续使用0.62饱和度令牌。

`tests/terrain-extension.cjs` 验证375×812、390×844、430×932上的地形覆盖、图片加载、图集比例和点击穿透；`tests/fixed-screen.cjs` 继续验证两条路线及单屏操作。

## 底部面板两侧景物

游戏态新增 panel-terrain 底层，复用现有延展图的下方景物，覆盖操作面板两侧及底部安全区域。保持图片原比例和0.62饱和度；地图末端以32px过渡衔接到底层。该层不接收点击，不出现在首页与结算页。

## V2.0 交互与多关卡补充（现行）

第一关沿用原有构图及延展。第二至六关采用无建筑地形底图、透明建筑图集、配置道路/节点、页面 UI 四层。各关节点与边由关卡配置决定，建筑脚点依节点锚点布置；5节点图使用较大建筑，7节点图缩小建筑以保持道路与点击区可见。新增建筑滤镜 `--modular-saturation:.55`；其余插画保持 `.62`。

仓库阶段：随身负重为0，单独展示“仓库铁钱”和“拟装载”。不再把仓库8铁钱计入人物负重。货物单列成紧凑物品行；交易面板保留两个独立金额选择器，按钮44px。旅行态面板收缩，不空占交易空间。

点击任意地点可看公开条件；相邻且可支付时才显示确认移动。规则弹层根据该关交易数量分页。教学采用底部角色短卡，地图保持可见；继续或跳过后恢复完整底部操作；跳过、重放序幕、三级提示不耗步。错误信息使用具体金额/重量差额，保留必要反馈，不恢复常驻说明小字。

票据共用现有位图，加甲/乙/官代码印记与文字，避免只靠颜色区分。颜色在 tokens.css 集中维护。不使用 Emoji、SVG 建筑或字母头像；0.4.1 接入可替换的透明人物位图。

与参考图主要差异：第一关仍使用参考构图图集；后五关为模块布局，尚未达到参考图各商铺独有陈设的细节。当前通用商铺会复用，缺人物正式定稿和独立票面。资源替换只影响场景/展示配置，不影响价格、道路和胜利判定。

## 0.4.1 叙事界面（现行）

- 首页：游戏名及副标题、场景与阿禾组合、当前章节任务、六段通关进度、继续章节及次级入口。继续章节沿用原有最近章节行为，不引入中途存档。
- 章节：2列×3行固定屏，局部场景缩略图、编号、标题、叙事副标题和状态。未解锁使用低彩度并保留可读状态，不仅靠颜色区分。
- 开场：章节标签、标题和一行引导；中央场景＋当前说话角色；叠放委托卡；目标与动态步数/容量；开始与跳过。角色层和场景层独立。
- 常规对白：底部约202px卡，125×181px角色区域、右侧正文、继续/跳过；背景不接收对白遮罩点击，地图仍可操作。卡下的操作需先继续或跳过。
- 重要对白：约300px半屏卡，160×254px角色区域；地图保持可见，单击“继续行商”收起。重播不改变状态。
- 结尾：角色头像和自然回应，随后展示真实路线、费用与余额。失败由阿禾提示撤销，再显示具体失败原因。
- 节点：公开交易条件前增加一句地点氛围提示。费用和规则继续由原 presenter 生成，不在叙事配置中复制数值。

新布局参数统一在 `miniapp/styles/narrative.css`：圆角24/18/17px、主间距14px、正文14px、开场标题34px、人物饱和度0.76；沿用 tokens.css 的米白、灰蓝和暖棕。主按钮50px，次级触控44px。三种目标手机尺寸保持单屏；不添加常驻免责声明、不添加额外滚动区。

共享展示装饰器 `miniapp/ui/narrative.js` 仅接收视图并附加角色/文案/缩略图数据，不调用规则状态变更。浏览器与原生页面使用同一份叙事配置。角色为生成临时生产资源，不等于最终角色设计；差分和表演留待P2。

## 0.4.2 人物风格修正（覆盖先前人物方向）

用户明确否定0.4.1半写实人物。当前三位角色改用与微缩地图相配的二维块面卡通：略放大的简化头部，深色椭圆眼睛、楔形鼻、小嘴；头发和衣褶使用少量大色块，只有轻微2.5D体积感。保持灰绿、蓝灰和暖棕。禁止真人肖像、半写实皮肤与毛发细节、摄影光影、油画质感、厚黑描边和动漫偶像式五官。

角色资源仍为独立透明PNG，沿用同一接入路径。首页、开场、底部对白、半屏剧情与结尾全部同步，不保留旧人物混用。正式角色定稿仍需验收，不因替换画风改变UI或规则。

## 0.4.3 操作入口融入界面

移除钱袋面板底部独立的“撤销／提示／剧情／重试”工具栏。撤销与行动步数并列，保留44px触控区和禁用状态；提示变成当前操作标题旁的阿禾角色入口“问阿禾”；剧情重播与重试分别以“重听委托”“重新启程”收进右上角“行商手记”菜单，菜单同时提供规则与章节入口。钱袋底边仅保留12px内边距，地图随可用高度延展，不预留空工具栏。

菜单只管理视图，打开与收起不耗步、不改资产；打开期间禁止触发地图移动或背后交易。重试仍调用既有完整重置，撤销与三级提示规则不变。浏览器和小程序使用同一控制器状态。

## 0.4.4 插画章节商路与结尾史话

章节入口改成共享地形上的六处微缩场景，按左右错落的商路串联；不再使用六张重复地图裁切卡。每处场景下保留实时编号、标题和进度，待解锁场景仍保留图画与克制色彩。角色、章节标签、路线和状态均独立于图片，插画不烘焙文字。章节连接线只代表章节顺序，与六关内部的可走道路无关。

六关通关回应各融入一小段相关史话，话题为铁钱携带、钱券并用、商号信任、茶货往来、兑付困难及官交子。使用既有角色对白卡，不弹出强制阅读页面。史料出处集中在 docs/history-sources.md，不增加常驻免责声明。首页移除“交子史话”独立按钮。

页面刷新统一进入游戏首页，继续按钮由用户主动点击；已解锁与通关记录保留。浏览器缓存返回也收起上次界面和弹窗回首页。
