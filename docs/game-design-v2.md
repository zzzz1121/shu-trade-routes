## 0. 文档阅读与实施约定

### 0.1 一句话定义

一款以北宋蜀地交子文化为背景的**单局独立、可反复挑战的轻策略解谜游戏**。玩家扮演年轻行商，通过选择铁钱与交子、控制负重、规划商路、完成买卖，在六个委托中体验货币流通与信用问题。

### 0.2 优先级与边界

| 层级 | 必须实现或坚持 | 暂不实施 |
|---|---|---|
| 核心循环 | 接委托 → 准备资金/货物 → 移动 → 买卖/兑换 → 交付 → 结算 | 开放世界、大地图经营 |
| 策略 | 负重、混合支付、步数、商户接受条件、多种合法解法 | 随机抽卡、体力、强制等待 |
| 剧情 | 固定主线、局部条件对白、每关简短开场与结尾 | 大规模多结局文本树 |
| 教学 | 在实际交互处触发，支持跳过、提示与撤销 | 长篇纯文字教学 |
| 美术 | 已确认的现代数字插画＋斜俯视微缩地图；现有人物方向 | 水墨做旧、浓重古风厚涂 |
| 技术 | 数据驱动关卡、独立规则引擎、可验证测试 | 账号、付费、排行榜、长线养成 |

### 0.3 与既有方案的区别／修订

1. **第一关正式名称统一为《布匹之约》**，不使用旧版名称。
2. **区分货仓与随身资产**：第一关初始 **8 单位铁钱在货仓**，并非人物已经携带 8 铁钱；钱袋载重上限仍为 5。
3. 货币的“数额”与“重量”是独立字段；铁钱每单位占 1 格，交子每单位占 0 格，商品增加指定负重。
4. 第一关桥费以 **1 单位铁钱**扣除，移动只沿图上的边，每走一条边记 1 步；先前视觉样图里的“100/100”“10 步”“20 桥费”等数字**全部作废**。
5. 第二关固定两家商铺的支付要求，支持**先粮后药**与**先药后粮**，但必须满足中间状态的负重限制。
6. 第四至六关已细化为可执行的资源表、拓扑和样例解法，禁止以概念描述替代实际规则。
7. 不以“交子总比铁钱更好”为叙事结论；加入使用范围、信用与兑付限制。
8. 下文的“合法交易组合数量”是**给定预设路线、固定价格、整数支付条件下的枚举结果**，不是试玩得出的趣味性指标。

## 1. 产品定位与玩家体验

| 项目 | 定义 |
|---|---|
| 类型 | 二维轻策略解谜 × 微量互动叙事 × 文化主题 |
| 主要平台 | 手机竖屏小红书小程序，开发期可配浏览器调试入口 |
| 目标用户 | 喜欢轻解谜、路线规划、资源组合、独立游戏视觉的泛游戏用户；不要求预备历史知识 |
| 单关时长 | 约 3—7 分钟（第一次带教学略长） |
| 全主线 | 六关，预计约 25—35 分钟，不计反复重试 |
| 重玩动力 | 多种合法解法、步数／成本优化、不同账本结果 |
| 传播内容 | 根据真实操作记录生成「行商账本」结果卡（后续阶段开发） |
| 不采用 | 连续签到、强制日活、体力墙、抽卡、付费加速、长时间等待 |

### 1.1 体验支柱

1. **看得见的策略**：钱币、票据、货物、负重以可观察对象呈现，变化即时反馈。
2. **同题多解**：通关不等于唯一最优；短路付费与绕路省钱可以同时成立。
3. **规则就是文化**：沉重铁钱、轻便交子、不同商户的收付条件构成题目，而不是读完题再答知识问答。
4. **对话不打断思考**：教程只在需要时出现，老机制不反复提示。
5. **操作轻量**：优先点击、选择金额、确认；正式拖拽可增强但不作为首版必需条件。

### 1.2 胜负与表现评价

- **通关必要条件**：在步数上限内，完成该关全部指定交易和交付；所有中间状态合法。
- **无法操作**：不足额、超重、错误票据、非相邻节点、无资格过桥等操作不生效，并解释原因。
- **关卡失败**：已消耗行动且不存在完成目标的可行路径，或在行动上限后仍未交付；系统提供撤销和立即重试。必要时可允许玩家主动认输重置。
- **表现评价**：行动效率、交易成本、最终保留资产、特定风险应对。评价彼此独立；高评价**不阻断**下一关解锁。
- **时间**：不设置实时倒计时；思考时间不记为步数。

## 2. 故事设定与历史边界

### 2.1 世界与时间

故事发生于**北宋蜀地，以益州（今成都一带）商贸环境为主要背景**。前五关发生在民间交子流通及信用问题受到关注的时期；第六关通过明确的「一段时间后」转场进入官交子阶段。**不规定前五关逐关跨越多年**，避免人物年龄、事件先后被误解为真实年表。

### 2.2 主线主题

> 从“钱够却带不动”，到“轻便的纸，凭什么能当钱用？”

三幕结构：

- **第一幕／初入商路（01—02）**：初次采购，学习货币与负重的关系。
- **第二幕／一纸之信（03—05）**：商号之间的接受差异、货物周转及兑付压力。
- **第三幕／新的流通（06）**：在官交子的历史转折背景中完成综合委托。

故事不采用“好人信任交子、坏人拒绝交子”的二元评价。商人接受不同支付方式是交易条件，玩家要分析其成本与风险。

### 2.3 可明确陈述的史实

| 主题 | 可采用的历史表述 | 来源编号 |
|---|---|---|
| 铁钱重量 | 北宋四川铁钱沉重，大宗交易携带不便，推动了交易票据的发展。 | H1、H2 |
| 民间交子 | 交子先有民间铺户经营、收取现钱并开出票据，信用与兑现能力关系重大。 | H1、H2 |
| 信用问题 | 史料与研究记录了民间交子经营中的诈伪、兑付纠纷等问题。 | H2 |
| 官办转变 | 天圣元年（通常表述为 1023 年）设置益州交子务，次年开始发行官交子；具体设务日期换算为公历时可能跨入 1024 年。 | H1、H2、H3 |
| 纸币形态 | 早期票据存在铺户印记、图案、题号等防伪手段，但**不得据此声称某张游戏票面是可考的完整复原实物**。 | H2 |

> 日期校核：史料使用年号与农历，部分现代报道将“天圣元年十一月二十八日”换算为 **1024-01-12**，而通行历史概述仍写“1023 年设务，1024 年官交子发行”。游戏正文统一用“天圣元年设益州交子务，次年官交子发行”的相对表述；若展示公历年份，附上述换算说明。

### 2.4 必须标注为虚构／抽象的内容

- 玩家、阿禾、罗掌柜、许掌柜及各商户身份和台词。
- “甲号／乙号交子”及两铺之间的固定换票比例；这是**模拟接受范围与信用差异的教学模型**，不是具体史实。
- 第一关兑换「存 X 铁钱、得 X−1 交子」，各关手续费、桥费、价格、路程、货物重量和“负重格”均为**抽象游戏数值**。
- 第五关许记的“最多兑付 3 单位”和免手续费规则为虚构关卡条件。
- 第六关官交子的商户接受规则与购买价格为教学设定；不宣称官交子在真实历史上处处通兑、完全没有风险。
- 地图是**架空的蜀地商镇示意**，不是北宋成都地理复原图；桥梁收费也非真实特定桥梁史实。

**适合展示给玩家的一行说明**：

> “人物、商路与交易数字为游戏化设定；交子相关历史背景参考博物馆资料与货币史研究。”

## 3. 人物设定与叙事关系

### 3.1 角色总表

| 角色 | 身份／功能 | 外在性格 | 剧情成长 | 美术设定 |
|---|---|---|---|---|
| 玩家 | 刚开始独立接单的年轻行商 | 由操作决定，不预设性别与姓名 | 从受指引到独立判断 | 第一版可不做正面主角立绘，地图用小行商标记 |
| **阿禾** | 同行伙伴／前期教学引导 | 机灵、利落、亲和、不说教 | 由“带你做”转为“和你商量” | 年轻女性，半束发或低马尾、灰绿短外衫、米白内搭、斜挎包和钱袋；沿用当前已制作的立绘方向，不再重新改风格 |
| **罗掌柜** | 商行经营者／贯穿委托人 | 沉稳、务实、可靠 | 对玩家逐渐放手 | 中年男性，深棕与青灰服饰，随身账本，普通商人而非富贵官员 |
| **许掌柜** | 民间交子铺经营者／信用议题人物 | 斯文、谨慎、克制 | 从从容到承压，最后理解新的制度变化 | 清瘦的成年男性，蓝灰或墨青服饰，持票据／账册，不作为脸谱化反派 |
| 布商／粮商／药铺等 | 交易规则 NPC | 简单、各有交易习惯 | 主要服务对应关卡 | 可用半身小插画／头像，首版无需每人全身立绘 |

### 3.2 立绘范围与表现约束

- 阿禾：默认、认真提醒、思考、惊讶／担忧 **4 表情**；一套固定基础姿态优先。
- 罗掌柜：平静、满意、为难 **3 表情**。
- 许掌柜：平静、思索、担忧、释然 **4 表情**。
- 主要角色用于剧情页与短对话；地图上可以只有简化角色标记，**不必显示大立绘遮挡解谜**。
- 人物保持此前当前版本方向：**自然比例、干净线条、柔和低饱和色块、普通宋代商旅服饰的现代化简化**。避免油润厚涂、网红古偶脸、夸张 Q 版、仙侠发饰、强水墨与柔光背景。
- 当前阿禾生成图属于**视觉方向参考**，不能默认是可直接切图的透明正式资产；真正投产时须获得无背景版本和稳定的表情差分。
- 不随意把人物进一步改为高精度 Galgame 立绘；用户已决定保持当前方案。

### 3.3 对话口吻

- **阿禾**：口语化、简短、有观察力；不替玩家报答案。
- **罗掌柜**：任务明确，关心是否按时交付；不发表冗长历史感言。
- **许掌柜**：讲交易规则与商号信用，用事实和处境说话，不充当说教员。
- 每段普通对话尽量 **1—3 句**；首次必看导入在 **30—45 秒以内进入操作**；结算正文不超过三四句。

## 4. 通用游戏规则／规则引擎契约

### 4.1 资源与单位

| 项目 | 规则 |
|---|---|
| 铁钱 `iron` | 每 1 单位价值占 **1 格负重**；部分收费点、商户要求必须付铁钱 |
| 民间交子 `notes.a`／`notes.b` | 每 1 单位面值占 **0 格负重**；仅可在接受对应商号的商户使用 |
| 官交子 `notes.official` | 第六关使用，0 格负重，按该关商户规则支付 |
| 货物 `cargo` | 每种货物设价格、重量、持有量、目标状态；购买获得重量，出售移除重量 |
| 当前负重 `load` | `iron + Σ(货物数量 × 货物重量)`；**交子不计入** |
| 负重上限 | 全六关默认 5 格，未来可配置 |
| 行动 `stepsUsed` | 每沿一条**已连接边**移动记 1 步；支付、交易、兑换、对话不记步数 |
| 单位价值 | 铁钱／交子支付按关卡定义的抽象 1:1 价值单位相加；显式兑换或换票除外 |

### 4.2 通用行动优先顺序

1. 玩家选择一个可见的相邻节点，先**预览**所需步数、桥费或限制条件。
2. 确认移动前验证是否可达、是否超过行动上限、是否可承担费用。
3. 若进入收费节点，**验证费用足额后**扣费，再设置新位置并增加 1 步；必须原子执行。
4. 进入商铺后，可打开支付面板，验证总价、商户接受类型、最少必付铁钱／交子、付款后负重。
5. **购买**：先扣支付的钱币，再增加货物重量；**出售**：先移除货物，再增加约定收款货币，随后检查负重。交易一并提交，不允许局部成功。
6. 完成所有采购后抵达指定交付点，记录最终交易轨迹并结算。

### 4.3 状态、交易与撤销

- 必备状态：`levelId`、`nodeId`、`iron`、`notesByIssuer`、`cargoById`、`stepsUsed`、`completedTransactions`、`routeHistory`、`redeemCount`、`tutorialFlags`、`status`。
- 第一关额外区分 `warehouseIron=8` 与人物 `carriedIron`；仓库阶段采用**出发准备状态**，兑换后剩余未兑换的铁钱为拟携带资产，只有满足 5 格负重才可出发。
- 第一关若选择 X 单位兑换：`2 ≤ X ≤ 8`；手续费固定消耗 1 单位价值，结果为 `carriedIron = 8−X`、`notes = X−1`。若不兑换，拟携带铁钱为 8，因超重不能出发；允许玩家重新选择。
- 正式移动开始后不能随时重新访问起点兑换柜台；要更改初始兑换方案，应撤销到出发准备状态或重试。
- 所有状态变更走统一命令／reducer；先校验，再一次性提交，并记录可撤销快照。
- 非法操作不扣钱、不消耗行动、不推进剧情触发，也不污染撤销历史。
- 成功通关属于**首次交付**，对同一委托重复提交必须拒绝。
- 失败/死局可撤销最近合法步骤，也可整关重试；不要求等待、支付或消耗体力。
- 关卡重玩默认跳过已完成的新手强引导，但规则说明和提示随时可查看。

### 4.4 地图与路线

- 地图为**带节点和边的图结构**，不应将自由点击背景误认为移动。
- 只能从当前位置移动到相邻节点；不可点击远处节点跳过收费、交易或行动消耗。
- 可显示已知所有节点的商户规则与相关费用，避免靠隐藏条件坑玩家。
- 除明确注明单向，否则边按可双向移动实现；**折返照样记步数与费用规则**，不得依靠折返绕开结算。关卡样例以不折返的预设路径为准。
- 对收费桥，进入时扣费；若实现双向进入重复收取会造成易误解，首版建议把收费节点定义为**首次经过本关收费一次**，回头移动仍记步但不再次收费；也可将桥定义为单向。**必须选择一种并写入代码**。为与既有“进入收费桥扣 1 铁钱”的规则一致，本版采用**每次进入收费桥均扣 1 铁钱**，并明确 UI 显示此规则；预设路线不受影响。
- 路线上的特殊操作仅在相应功能节点执行；同一商铺的委托交易最多完成一次。

### 4.5 提示与教学等级

1. **首次接触**：3—12 字的目标提示 + 高亮可操作组件。
2. **非法操作**：展示确切原因，例如“支付后将超重 1 格”，不只显示“操作失败”。
3. **主动求助**：第一层指出受限资源；第二层提示策略方向；第三层（需再次主动点击）可给出一组参考解法。默认不自动显示第三级。

## 6. 第一关《布匹之约》——完整规格

**教学目标**：携带重量、交子兑换、双路线、混合支付、交付。  
**主旨**：“钱够了，但钱袋装不下。”

### 6.1 配置

| 字段 | 取值 |
|---|---|
| 起点 | `warehouse` 货仓 |
| 初始仓库铁钱 | 8（尚未携带） |
| 兑换 | 起点一次：投入 X 铁钱，得 X−1 交子；X≥2 整数；手续费 1 |
| 可携负重 | 5 |
| 布料 `cloth` | 价格 6，重量 2 |
| 布铺支付条件 | 至少 2 铁钱，余额可用交子 |
| 收费桥 | 进入需 1 铁钱 |
| 最大步数 | 4 |
| 胜利目标 | 完成买布，并携布抵达交付商行 |

**地图节点与边**（合计 **6 个节点**，不要添加“汇合点”作为独立节点）：

```text
               收费桥 (bridge)
               /          \
货仓 (warehouse)            布铺 (cloth_shop) —— 交付商行 (delivery)
               \          /
                街巷 —— 后巷
              (street)   (back_alley)
```

- 上路：货仓 → 收费桥 → 布铺 → 交付，**3 步 + 1 铁钱桥费**。
- 下路：货仓 → 街巷 → 后巷 → 布铺 → 交付，**4 步，免费**。

### 6.2 已验证参考解法

| 操作 | 收费桥路线 | 免费街巷路线 |
|---|---|---|
| 货仓兑换 | 存 5 铁钱 → 得 4 交子 | 同左 |
| 出发携带 | 3 铁钱 + 4 交子，负重 3 | 同左 |
| 过路成本 | 桥费 1 铁钱 | 0 |
| 布铺支付 | 2 铁钱 + 4 交子 | 2 铁钱 + 4 交子 |
| 布料重量 | 2 | 2 |
| 交付步数 | 3 | 4 |
| 交付后剩余 | 0 | 1 铁钱 |

**穷举统计**：在起点兑换、规定的两条无折返路线及整数混合支付下，共 **10 种合法兑换／支付／路线组合**（收费桥 3 种，免费街巷 7 种）。这是逻辑检查，不是玩家测评。

### 6.3 序幕与教学脚本

**首次进入目标**：在 30—45 秒内让玩家开始第一次真正操作；教程通过实际行为触发。

| 触发 ID | 条件 | 角色台词（可直接使用） | UI／操作 | 完成条件 |
|---|---|---|---|---|
| `L01_OPEN` | 首次进入章节 | 罗掌柜：“布铺留了一批布，替我买回来，再送到商行。” | 委托卡显示目标与价格 | 关闭委托卡 |
| `L01_MONEY` | 首次打开货仓／钱袋 | 阿禾：“货款有八份铁钱。先看看钱袋能装多少。” | 高亮“仓库 8／容量 5” | 看过负重信息 |
| `L01_OVERLOAD` | 尝试携带超出 5 | 阿禾：“钱是够了，可袋子装不下。” | 明确显示超重数量，提示兑换 | 打开兑换面板（无需故意超重才能继续） |
| `L01_EXCHANGE` | 首次打开兑换界面 | 阿禾：“交子拿着轻便，不过兑换也要花钱。” | 预览兑换后铁钱、交子、负重、手续费 | 完成合法出发准备 |
| `L01_ROUTE` | 首次选择路线 | 阿禾：“走桥快，要付钱；绕路慢，不收费。” | 同时高亮桥与街巷，显示 1 铁钱／多 1 步 | 第一次合法移动 |
| `L01_SHOP` | 首次进入布铺 | 布商：“至少给我两份铁钱，其余可以用交子。” | 支付组合面板实时显示总额和交易后负重 | 成功购买布料 |
| `L01_FINISH` | 首次交付成功 | 罗掌柜：“不错，这笔生意办成了。” | 结算显示实际路线、费用、余额 | 玩家确认结算 |

**条件结算补充**：

- 经收费桥：阿禾：“省了一段路，不过也付了桥钱。”
- 经免费街巷：阿禾：“多绕了些路，倒是省下了桥钱。”
- 下一关钩子：罗掌柜：“下回可不止买一样东西。”

**失败引导**：

- 负重超限：“当前负重超过上限 {delta} 格。”
- 没有桥费：“经过收费桥需要 1 铁钱。”
- 票据过多而铁钱不足：“布铺要求至少 2 铁钱。”
- 不足 6 单位货款：“货款还差 {delta} 单位。”
- 想从仓库直接跳到布铺：“只能前往相邻地点。”

## 7. 第二关《两笔买卖》——完整规格

**教学目标**：两次采购的先后顺序、支付结构与**中间负重**。  
**故事任务**：罗掌柜同时需要粮食和药材。

### 7.1 配置

| 字段 | 取值 |
|---|---|
| 初始携带 | 5 铁钱 + 4 交子；初始负重 5 |
| 负重上限 | 5 |
| 粮食 | 价格 4，重量 3；至少支付 3 铁钱，其余可用交子 |
| 药材 | 价格 4，重量 1；至少支付 3 交子，其余可用铁钱 |
| 兑换 | 本关无兑换 |
| 最大步数 | 4 |
| 胜利目标 | 两种货物都购买并交付 |

**地图与路线**：关卡使用五个节点：`warehouse`（货仓）、`grain_shop`（粮商）、`medicine_shop`（药铺）、`side_street`（街尾）、`delivery`（交付）。**以下无向边集合为唯一权威拓扑**：

`warehouse—grain_shop`、`grain_shop—medicine_shop`、`medicine_shop—delivery`、`warehouse—medicine_shop`、`grain_shop—side_street`、`side_street—delivery`。

- 先粮后药：`warehouse → grain_shop → medicine_shop → delivery`，**3 步**。
- 先药后粮：`warehouse → medicine_shop → grain_shop → side_street → delivery`，**4 步**。
- 同一商铺完成委托后不能重复购买第二份。

### 7.2 参考解法

**先粮后药**：粮商支付 3 铁钱 + 1 交子，持有 2 铁钱和粮食 3 格（负重 5）；药铺支付 1 铁钱 + 3 交子，再获得药材 1 格；最终携带 1 铁钱 + 4 格货物（负重 5），剩余价值 1。

**先药后粮**：药铺先支付 1 铁钱 + 3 交子，携带 4 铁钱 + 药材 1 格（负重 5）；粮商支付 3 铁钱 + 1 交子，获得粮食 3 格；最终 1 铁钱 + 4 格货物，负重 5。

**穷举统计**：在两种采购顺序的预设路线和整数支付范围内，共 **5 种合法支付／顺序组合**。

### 7.3 剧情与教学事件

| 触发 | 台词 | 教学与反馈 |
|---|---|---|
| 接单 | 罗掌柜：“这回有两样东西要买。两家铺子的收钱规矩不一样。” | 委托显示两张采购单，允许查看规则 |
| 首次查看店铺 | 阿禾：“先买哪一样，也得算算钱袋装不装得下。” | 同屏查看两家支付条件 |
| 购买后超重 | 阿禾：“别光看货款，买回来的东西也有重量。” | 展示“付出铁钱→腾空间→新增货物”的模拟预览 |
| 完成两单 | 阿禾：“原来买卖的顺序，也是一笔账。” | 结算保留实际先后顺序 |
| 结尾过渡 | 阿禾：“可要是两家铺子认的交子不一样呢？” | 引出第三关 |

**注意**：玩家不能被强制先去粮商；先药后粮也是合法路线。

## 8. 第三关《谁信这张纸？》——完整规格

**教学目标**：票据商号与接受范围／换票成本。  
**故事任务**：完成一笔相同货物的采购，东市和西市条件不同。

### 8.1 配置

| 字段 | 取值 |
|---|---|
| 初始携带 | 4 铁钱 + 4 **甲号**交子 |
| 负重上限 | 5 |
| 货物 | 重量 2；东、西市购得均视为同一任务目标 |
| 东市 | 价格 6；接受甲票与铁钱；至少 2 铁钱 |
| 西市 | 价格 4；必须至少支付 3 **乙号**交子；剩余允许用铁钱 |
| 换票铺 | 固定整笔：4 甲票 → 3 乙票；只可换一次 |
| 最大步数 | 3 |

**地图边集合**：`warehouse—east_market`、`east_market—delivery`、`warehouse—exchange`、`exchange—west_market`、`west_market—delivery`。无其他捷径。

- 东市：`warehouse → east_market → delivery`，2 步。
- 西市：`warehouse → exchange → west_market → delivery`，3 步。

### 8.2 参考解法

- **快捷方案**：东市支付 2 铁钱 + 4 甲票，货物重量 2，剩 2 铁钱，2 步交付。
- **省钱方案**：先将 4 甲票换成 3 乙票；西市支付 1 铁钱 + 3 乙票；货物重 2、剩 3 铁钱，3 步交付。

**穷举统计**：东市混合支付 3 种，西市换票后支付 1 种，合计 **4 种合法组合**。

### 8.3 剧情与教学

| 触发 | 台词 | UI 教学 |
|---|---|---|
| 接单 | 阿禾：“东市收这张票，西市却不认。” | 显示甲、乙票据的**商号标记** |
| 看西市规则 | 西市商人：“这里收乙号交子。” | 不是失败才公布规则，商户资料始终可查看 |
| 看换票 | 许掌柜：“换了商号，花钱的地方也不同。” | 显示 4 甲 → 3 乙的成本 |
| 选东市 | 阿禾：“少走路，倒也省事。” | 结算记录“东市” |
| 选西市 | 阿禾：“换票费了一点，货却便宜些。” | 结算记录“西市” |
| 结尾 | 许掌柜：“一张纸为什么值钱？得有人愿意认，也得有人能兑现。” | 为兑付风波埋伏笔 |

> “甲号／乙号”是游戏虚构的教学分类，不要做成真实历史商号的考证断言。

## 9. 第四关《转手生意》——完整规格

**教学目标**：先出售，再采购；收款货币形式改变负重与路线。

### 9.1 剧情导入

罗掌柜：“这回先卖茶，再买布。我只交代买卖，路怎么走、钱收成什么样，你自己定。”  
阿禾：“这次收铁钱，还是收交子？”

### 9.2 配置

| 字段 | 取值 |
|---|---|
| 初始随身资金 | 2 铁钱 + 2 交子 |
| 初始货物 | 茶包 1 份，重量 2 |
| 负重上限 | 5；开局负重 `2 铁钱 + 2 茶包重量 = 4` |
| 茶行 | 必须卖出茶包；售价 3，整笔收 **3 铁钱**或 **3 交子**二选一 |
| 布坊 | 布料价 6，重量 2；至少支付 2 铁钱 |
| 收费渡口 | 进入扣 1 铁钱 |
| 最大步数 | 5 |
| 胜利目标 | 茶包已卖出、布料已买入并交付 |

**地图边集合**：`warehouse—tea_shop`、`tea_shop—toll_crossing`、`toll_crossing—cloth_shop`、`tea_shop—street`、`street—back_alley`、`back_alley—cloth_shop`、`cloth_shop—delivery`。

- 收费路线：`warehouse → tea_shop → toll_crossing → cloth_shop → delivery`，**4 步**。
- 免费路线：`warehouse → tea_shop → street → back_alley → cloth_shop → delivery`，**5 步**。

### 9.3 参考解法

**快：收铁钱／走收费路**：开局 2 铁钱 + 2 交子 + 茶包（重 4）；在茶行卖茶收到 3 铁钱，现为 5 铁钱 + 2 交子（重 5）；付过路费 1 铁钱，布坊付 4 铁钱 + 2 交子，带布交付，4 步，余额 0。

**省：收交子／走免费路**：卖茶后 2 铁钱 + 5 交子（重 2）；绕行至布坊，付 2 铁钱 + 4 交子，带布交付，5 步，剩 1 交子。

**穷举统计**：限定茶行整笔收款类型及预设两路线，**4 种合法交易组合**。注意“卖茶收 3 交子但又走收费路线”无法满足后续“布坊至少 2 铁钱”的要求，属于可推理的死路；提示或撤销应可用。

### 9.4 剧情与教学

| 触发 | 对话 | 玩法反馈 |
|---|---|---|
| 出发 | 罗掌柜：“卖了茶，再替我买布。” | 目标列表“卖茶”“买布”“交付” |
| 首次进入茶行 | 阿禾：“先想想收什么钱，钱袋也会变重。” | 收款类型二选一，预览交易后负重 |
| 选择收铁钱 | 阿禾：“现钱方便付费，可也真沉。” | 钱袋格子随收款增加 |
| 选择收交子 | 阿禾：“轻便倒是轻便，付现钱的地方还得留意。” | 票据数额变化、货物移除 |
| 通关 | 罗掌柜：“这回的周转，做得像样。” | 结算标记收款选择和路线 |

## 11. 第六关《新交子》——完整规格

**教学目标**：综合前五关机制；没有强制手把手教程。  
**历史情境**：以益州交子务设立、官交子发行的制度变化为章节背景；玩家的具体委托仍然是虚构事件。

### 11.1 剧情开场

**过渡字幕**：“一段时间后，交子的发行和管理开始出现新的变化。”  
**简明知识卡**：“天圣元年设置益州交子务，次年官交子发行。”  
罗掌柜：“如今有了新的交子，这笔买卖，你应该能独立办妥了。”  
阿禾：“这次我不替你算了。”

### 11.2 配置

| 字段 | 取值 |
|---|---|
| 初始携带 | 4 铁钱 + 5 官交子；负重 4 |
| 负重上限 | 5 |
| 布料 | 价格 4、重量 2、至少支付 2 铁钱，其余可用官交子 |
| 茶货 | 价格 4、重量 1、至少支付 3 官交子，其余可用铁钱 |
| 收费桥 | 1 铁钱 |
| 最大步数 | 5 |
| 胜利目标 | 买回布料 + 茶货并交付 |

**地图边集合**：`warehouse—toll_bridge`、`toll_bridge—cloth_shop`、`warehouse—street`、`street—back_alley`、`back_alley—cloth_shop`、`cloth_shop—tea_shop`、`tea_shop—delivery`。

- 收费路线：`warehouse → toll_bridge → cloth_shop → tea_shop → delivery`，**4 步**。
- 免费路线：`warehouse → street → back_alley → cloth_shop → tea_shop → delivery`，**5 步**。

### 11.3 参考解法

**快速**：4 铁钱 + 5 官交子出发；过桥付 1 铁钱，剩 3 铁钱 + 5 官交子；买布付 3 铁钱 + 1 官交子（布重 2）；买茶付 4 官交子（茶重 1）；4 步交付，剩余资金 0，货物重 3。

**节省资金**：走免费路线；买布付 2 铁钱 + 2 官交子；买茶付 1 铁钱 + 3 官交子；5 步交付，剩余 1 铁钱；总负重 4（铁钱 1 + 货物 3）。

**穷举统计**：按上述固定先布后茶顺序及两条预设路线，共 **6 种合法支付／路线组合**（收费 2 种，免费 4 种）。

### 11.4 收尾脚本

罗掌柜：“头一回叫你送布，你还在为钱袋发愁。如今两笔生意，已经算得清楚。”  
阿禾：“以后做生意，还会有新的难题吧？”

显示通关账本，按实际完成状态呈现路线与支付组合：

- 快捷路线 → “这一趟走得快，开销也多些。”
- 免费路线 → “多走几步，留下了一份钱。”

**收束文本**：“钱的样子变了，做生意的账，还得继续算。”

### 11.5 历史叙事提醒

官交子不应在游戏中被绝对化为“永远安全”“任何商家都必须接受”。本关设定只是让玩家在**已公开的接受条件**下重新整合此前学过的策略。

## 12. 完整教学与交互脚本系统

### 12.1 开场导入节奏（第一关）

| 时间目标 | 玩家看到／听到的内容 | 必须做到 |
|---|---|---|
| 0—8 秒 | 布匹委托、目标地点、人物简短对话 | 可点击跳过；没有长篇背景介绍 |
| 8—20 秒 | 货仓 8 铁钱、钱袋最多 5 格 | 仓库与随身资源清楚区分 |
| 20—45 秒 | 尝试准备携带／打开兑换 | 由困境引出交子，不强制玩家故意失败 |
| 45 秒后 | 玩家自由尝试兑换、选路、支付 | 仅在必要节点弹引导 |

### 12.2 通用剧情触发优先级

1. **规则错误反馈**（即时、原地显示）优先级最高，但不强制打断当前面板。
2. **首次机制教学**在玩家第一次接触操作时触发；一次只强调一件事。
3. **节点剧情**进入对应节点后触发；通常 1—2 句。
4. **章节结算**在胜利条件满足后触发，不得提前。
5. **历史知识卡**在结算页由玩家主动展开，或以短卡可跳过显示。

### 12.3 四类交互事件统一模板

| 类型 | 触发时机 | 动作 | 是否可跳过 |
|---|---|---|---|
| `onLevelEnter` | 章节首次进入 | 任务开场、角色对话 | 是 |
| `onPanelFirstOpen` | 某类面板首次开启 | 强调支付／兑付新规则 | 是 |
| `onInvalidAction` | 用户尝试非法操作 | 显示具体数字原因 | 不跳，但可立即关闭提示 |
| `onNodeEnter / onTransaction / onLevelComplete` | 移动、交易、完成后 | 条件对白与结算 | 剧情可跳，结算数据必须保留 |

### 12.4 第一次、重复游玩的表现

- 首次：人物对话 + 操作高亮 + 必要的支付规则提示。
- 重玩：只保留必要规则标识与错误反馈；默认不重播序幕。
- 用户主动点击“重新观看剧情”，可以回看，但不改变资源与行动。
- 跳过剧情不会跳过必要的规则校验，也不会改变可行路径。
- “提示”不扣关卡步数；可以在结算中标记“使用过提示”，但不得因此阻断进度。

### 12.5 关键错误反馈文案

| 错误码／条件 | 建议文案 |
|---|---|
| `OVERWEIGHT` | “超过负重上限 {delta} 格。” |
| `INSUFFICIENT_FUNDS` | “还差 {delta} 单位货款。” |
| `IRON_REQUIRED` | “这家店至少需要 {minIron} 铁钱。” |
| `NOTE_ISSUER_NOT_ACCEPTED` | “这家铺子不接受当前商号的交子。” |
| `REDEEM_LIMIT` | “今日最多可兑 {limit} 单位。” |
| `NOT_ADJACENT` | “只能前往相邻地点。” |
| `TOLL_IRON_MISSING` | “过桥需要 {fee} 铁钱。” |
| `NOT_PURCHASED` | “还没有买齐委托货物。” |
| `STEP_LIMIT` | “剩余步数不足以完成这次移动。” |
| `TRANSACTION_ALREADY_DONE` | “这笔委托已经交易完成。” |
| `WAREHOUSE_NOT_READY` | “先整理好出发的钱袋。” |

### 12.6 提示策略：不破坏谜题

| 层级 | 样例（第一关） |
|---|---|
| 1：资源提醒 | “想想怎样减少随身铁钱的重量。” |
| 2：策略方向 | “去兑换一些交子，但要留足布铺收的铁钱。” |
| 3：示例方案 | “可以先把 5 铁钱换成 4 交子，再比较两条路。” |

只有主动打开第 3 层，才出现具体数值方案。

## 13. 页面信息架构与移动交互

### 13.1 页面

1. **首页**：标题《蜀地钱路》／开始游戏／继续章节／规则与史料入口。
2. **章节列表**：六关名称、是否已通关、重玩，不出现体力限制。
3. **任务导入**：角色短对话＋委托目标；首玩简短，重玩可跳过。
4. **游戏主界面**：顶部状态＋中央地图＋底部可操作钱袋／货币面板。
5. **地点弹层**：兑换、支付、卖货、兑付、交易要求；不频繁整页跳转。
6. **结算页**：是否完成、路线、行动、花费、剩余资产、剧情反馈、重试／下一关。
7. **行商账本（后续）**：六关操作记录和分享结果卡；不影响核心通关。

### 13.2 主界面布局

| 区域 | 初步空间比例 | 核心内容 |
|---|---|---|
| 顶部 | 约 12% | 任务摘要、步数、负重、菜单 |
| 地图 | 约 55% | 微缩商镇、建筑、道路、当前位置／可达节点 |
| 底部 | 约 33% | 5 格钱袋、铁钱／交子／货物、当前地点操作与撤销 |

这仅是视觉起点；实际适配须考虑设备安全区、竖屏尺寸和交易面板展开状态。不要为了保持百分比而裁切地图核心节点。

### 13.3 核心交互

- **点击建筑节点** → 先展示名称与移动成本 → 确认移动。
- **点击相邻道路节点** → 当前可达标记轻亮；非相邻不可执行。
- **兑换面板** → 用 ± 按钮调整数额，实时预览费用、兑换后钱数与负重。
- **混合支付盘** → 分别调铁钱／对应交子数，实时显示合计、最低币种要求、交易后负重；合法才可确认。
- **卖货收款** → 选“收铁钱／收交子”，预览变化后确认。
- **撤销** → 恢复前一完整状态（余额、票据、货物、步数、节点、交易标记）；不是只把数值视觉上减回去。
- **重试** → 重置该关配置状态；不回滚历史已解锁章节。
- **教程高亮** → 引导可跳过，不锁住所有其他控件；原则上不做长操作流程强制锁屏。

### 13.4 表现评价与分享结果

- 基础通关后至少展示：关卡名、实际路线、步数、铁钱／交子支付、最终余额。
- 额外评价依据关卡独立目标，例如“快手行商”“精打细算”“周转有方”，可多标签并存，不把人物性格判断绝对化。
- 分享图可设计为个人行商账本，包含记录与票据、印章视觉；**分享接口与资质属于后续开发验证项**。

## 14. 已确认视觉规范与素材策略

### 14.1 总体视觉定向

- **正式已选方向**：干净的现代数字插画 × 斜俯视二维微缩建筑地图，接近轻量、清爽、少量 2.5D 的独立游戏视觉。
- **地图视觉锚点**：用户在对话中确认的那张六节点主界面参考图（包含低饱和草木、水渠、商铺、票据和底部钱袋）。正式工程需将该参考图另存为 `docs/references/approved-game-ui.png` 供 Codex 读取。
- 背景浅米白；地形淡绿与浅石色；水渠灰青蓝；灰瓦与木色建筑；布铺用少量砖红／靛蓝突出。
- **保留**：精致但简单的微缩建筑、明确双路、空白地表、统一商铺造型、干净的信息卡片。
- **禁止**：宣纸旧化、水墨晕染、雾气群山、复杂古镇全景、大面积金色、繁复浮雕、大量无功能花草、蓝紫霓虹、粗黑轮廓。
- 相比早期多张概念设定板，主游戏必须表现为**真实的竖屏交互界面**，而不是一整张信息说明板。

### 14.2 地图场景设计

- **中等细节密度，但留白明显**：不要让建筑和树木占满画面。
- 四个视觉锚点：货仓、收费桥、布铺、交付商行；街巷／后巷可作为环境化节点，不必都是一栋大建筑。
- 货仓在左，收费桥在上中，街巷／后巷在下方，布铺在右中，交付商行在右下；拓扑正确优先于视觉摆放。
- 建筑材质以简化灰瓦、木构、石桥、布幌为主，避免宫殿／寺庙式建筑误用。
- “当前”“可到达”“目标”“不可到达”节点用**程序绘制的状态标记**，不要烘焙进静态图片。
- 地图不能是无法维护的全景 PNG：至少分为地形、建筑、玩法节点／路径、UI 四层。

### 14.3 角色美术

- 沿用已确定的阿禾、罗掌柜、许掌柜设定；**不再重新选择人物立绘风格**。
- 初期以半身立绘、少量表情差分为主。主要人物服装有宋代市井参考，但人物、服饰细节并非严格考古复原。
- 必须保证不同表情的脸型、发型、衣着、视角一致；避免分别生图导致“换脸”。
- 人物不常驻遮挡主要地图；在对话面板中出现，教学完收起。

### 14.4 建议素材表

| 类型 | 最小资源 | 推荐处理 |
|---|---|---|
| 节点建筑 | 货仓、桥、街巷、后巷、布铺、商行 6 类 | 独立透明资产，分层放置 |
| 地形 | 地表、道路、水渠 | 优先程序路径＋少量可复用地块 |
| 装饰 | 树 2—3 款、箱笼、布卷、围墙、路牌 | 少量模块化复用，不抢功能信息 |
| 交易物件 | 铁钱、交子、布料、茶、粮、药、纸墨 | 独立 SVG／透明 PNG 或平台支持的绘制资产 |
| 动态状态 | 可达／当前／目标／禁用／收费 | 程序渲染，不与背景合成 |
| 主角立绘 | 阿禾 4 表情；罗掌柜 3；许掌柜 4 | 固定人物基础稿上制作差分 |
| 次要 NPC | 布商、粮商、药铺等 | 后续补齐，可以先使用简单头像 |

### 14.5 给 Codex 的资源交接原则

1. 检查当前工作区与 Git，先复用可用代码和合法素材。
2. 先完成数据规则与可玩的占位地图，不把 AI 生成的整图作为点击和规则状态唯一载体。
3. `assets/` 中将 `placeholder/` 与 `final/` 分开，场景图片与节点元数据分离。
4. 正式视觉参考应作为风格依据，**不应照抄其中可能错误的数字、桥费和地图连接**。
5. 若缺正式建筑资产，使用一致的矢量占位图，等审批后再换，不随意批量抓取图片。
6. 每个资产给出用途、透明背景需求、建议基准尺寸、锚点、缩放范围、是否可复用；人物表情记录一致的对齐点。

## 15. 开发实现边界与数据结构建议

### 15.1 建议模块拆分

| 模块 | 责任 |
|---|---|
| `levels/` | 六关初始资源、节点、边、商户规则、目标与剧情触发配置 |
| `engine/` | 纯 JS 状态计算：移动、换票、兑换、交易、购买、出售、交付、结算 |
| `tutorial/` | 首次触发、教学状态、提示级别与跳过标记 |
| `story/` | 角色台词、分支条件、历史提示卡数据 |
| `ui/` | 地图、钱袋、货币盘、交易弹层、结算与剧情展示 |
| `assets/` | 地形、建筑、角色、交易道具，正式与占位资源分开 |
| `tests/` | 关卡合法解、边界条件和状态回滚测试 |

### 15.2 关键校验与状态不变量

- 所有货币余额与货物数量均为非负整数。
- `load ≤ maxLoad` 对一切已提交状态成立；第一关仓库待出发预览状态可显示超重，但不能正式出发。
- 购买总支付值 = 商品价格；出售所得值 = 指定收购价。
- 扣过路费／兑换手续费后总价值按规则守恒（减少的价值仅来自费用或购买，不凭空产生）。
- 交子种类必须与商户接受条件匹配，不能互相自动换算。
- 每次移动最多相邻一步；`stepsUsed ≤ maxSteps`。
- 一次性交易不可重复领取商品、重复卖货或重复交付。
- 撤销必须同时恢复所有数值、位置、交易标记、路线历史以及与之绑定的剧情状态。
- 六关胜利只依赖可检查的数值与交易完成标记，不依赖立绘、动画、对白是否播放。

### 15.3 全六关最小验收清单

| 关卡 | 必须测试成功 | 必须测试失败／撤销 |
|---|---|---|
| 01 | 3 步收费桥、4 步免费路均可通关 | 超重、无桥费、铁钱低于商户要求、重试回仓库 |
| 02 | 两种购买顺序可通关 | 先以纯交子买药导致超重，交易不提交 |
| 03 | 东市直购、西市换票均可通关 | 甲票直接在西市使用被拒绝 |
| 04 | 收铁钱走桥、收交子绕路均可通关 | 收交子又去桥造成布坊现钱不足；允许撤销 |
| 05 | 东市混付、西市兑足 3 铁钱均可通关 | 兑付超额或不足以在西市采购时给出可恢复提示 |
| 06 | 4 步收费、5 步免费均可通关 | 两家商户支付币种不足、负重错误、提前交付 |

### 15.4 已复核的合法组合计数

| 关卡 | 合法组合数 | 计数边界 |
|---|---:|---|
| 01 | **10** | 兑换整数 X、两条无折返路线、布铺混付；收费 3 + 免费 7 |
| 02 | **5** | 两类购买先后、两商户整数支付组合；必须每步不超重 |
| 03 | **4** | 东市 3 + 西市 1；固定 4 甲换 3 乙 |
| 04 | **4** | 收铁／收交子，收费／免费路线，布坊混付 |
| 05 | **3** | 东市 2 + 西市 1；兑付 1—3，仅兑足 3 可走西市 |
| 06 | **6** | 收费 2 + 免费 4，依固定布坊→茶行顺序 |

> 统计通过对上述整数资金、负重、支付门槛、路线费用和中间负重进行穷举核对；实际实现中应转成自动化测试，不将“合法解数量”写成剧情或对玩家公开的答案。

## 16. 风险、未决项与避免返工的原则

1. **平台发布资格**：目标虽为小红书小程序，但策略游戏是否适用小游戏准入、主体、备案、工具支持等，需以最新官方渠道核查；**不得声称已获准上线**。
2. **故事历史准确性**：人物与商号均虚构；“1023 设务／1024 发行”的公历换算应采用统一口径，不编造具体历史商号或交子票面。
3. **视觉一致性**：已确认主界面地图方向，不再回到水墨古镇画法；人物当前方向保持，不随意重做高精度油润立绘。
4. **关卡教学质量**：在第一关实际试玩中验证是否能理解货仓资金与负重；第二关是否能体会“支付后货物增重”；第三关是否能区分甲乙交子。
5. **避免伪策略**：若某关明显只需套固定套路，则优先调整支付条件或道路成本，禁止通过强行增加剧情文本制造“复杂感”。
6. **操作可逆**：任何可能令局面无解的合法操作，都必须能通过撤销或重试迅速恢复；没有体力成本。
7. **所有数字配置化**：修改商铺价格、通行费用或初始货币后，重新跑全部关卡求解测试，避免破坏已验证的路线。

### 16.1 首次玩家试玩观察要点

不提前解释完整规则，找 3—5 名未参与策划的试玩者观察：

- 是否知道第一关的 8 铁钱在**仓库**而非**钱袋**。
- 能否通过交子兑换自己发现减轻负重的方法。
- 能否区分两条路线的行动／费用差异。
- 是否理解为什么第二关“先花钱再拿货”会影响负重。
- 第三关是否把“商户拒收甲票”理解为游戏逻辑，而非程序 Bug。
- 是否愿意重玩关卡比较路线与余额。
