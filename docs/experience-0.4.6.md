# 0.4.6：立绘、对白与操作状态

## 页面与组件

- 首页：使用已确认风格的阿禾立绘；中途刷新回首页后可继续原局面，显示所在地与已走步数。旧通关记录继续有效。
- 章节与开场：保留六章插画入口和浅米白配色；替换统一角色资源，删除视觉区重复小标题。开场新增可取消的「行商打算」。
- 主界面：金额增加按钮以实际持币和单笔价格中较小者为上限；兑付同时受持票量、柜上限额限制。控制器也执行相同限制，过期按钮不能绕过。
- 对白：底部人物条、重要对白卡；支持连续句、继续/跳过、规则询问分支、回看及返回原游标。菜单增加回看与回首页。常规教学仍可边看边操作。
- 结算：提高正文和账目字号，缩减重复留白；长账目可滚动，保留底部操作。成功后的撤销明确标为「返回交付前」。

## 角色资源与剧本接口

`miniapp/assets/characters/v3/` 保存阿禾、罗掌柜、许掌柜各六帧透明图集。使用内置 image_gen 生成，提示词记录在同目录 `prompts.json`。不覆盖旧立绘，便于回退。

每个角色固定一张图集，使用帧坐标切换普通、微笑、思考、疑惑、担忧、坚定状态，避免对白切换时随机换脸。罗掌柜生成图集的帧顺序与另两人不同，由 `ui/narrative.js` 显式映射。每条对白都有固定的 `id / speaker / text / expression / pose`，姿态演出目前由对应帧承载，没有另外叠加复杂动作动画。

`core/dialogue.js` 提供场景结构：`{id, lines, choices}`。选项为 `{id,label,next}`，`next:null` 返回地图。`ui.choices` 保存已选分支，`ui.backlog` 保存已经展示的对白。正式剧本到来后可替换场景数据；本轮仅拆分原委托和调用现有规则，没有新增人物关系或长篇剧情。

开场、提示、教学和结尾均有角色表现。新长篇正文尚未接入，所以现阶段仍是具备文游承载能力的六关原型，不能视为完整剧情版。

## 撤销、重复操作与存档

每次成功行动成对保存引擎状态和叙事/UI 快照。撤销恢复资金、发行方票据、货物、位置、步数、费用、事件、教学标记、对白、分支选择和支付选择。非法操作不加入历史；空撤销不显示虚假成功；已解锁章节不因撤销或重试而锁回。

`shu-trade-progress-v2` 继续保存解锁；独立的 `shu-trade-run-v1` 保存本局操作记录、对白游标和撤销快照。恢复时从初始状态逐条执行真实规则，不直接相信存档里的资金或货物。损坏、版本不符、锁定章节或非法记录被忽略。刷新仍先回首页，玩家点「继续行程」才恢复；完成或重新开始会清理/替换本局记录。存储失败会给出可继续游玩的提示。

## 难度评估

现有六章中，第一、三、四、五、六章主要是不同商路/货币选择，第二章主要是采购顺序和中途负重。限定参考路线组合数量为 10、5、4、4、3、6；这不等于完整游戏空间，也不代表成熟的剧情难度曲线。

本轮未改价格、容量、步数、地图、手续费、交付和解锁规则。新增的可选个人目标把既有取舍显出来：快路与免费路、直接买入与换票省款、兑付绕路与直接混付。结算回应目标是否做到；未做到不阻止通关、不扣钱。第二章目标是留一份铁钱，与最短路目标并非互斥。真正增加剧情决策深度，应随正式剧本补充选择后果，避免靠加数值或随机惩罚制造难度。
